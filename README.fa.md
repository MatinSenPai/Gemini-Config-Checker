# Gemini Config Checker

کانفیگ‌هایی را پیدا کن که واقعاً تو را به **Google AI Studio و Gemini** می‌رسانند. هر کانفیگ را همان‌طور تست می‌کند که یک آدم واقعی می‌بیند:
در یک **مرورگر لاگین‌شده** و از مسیری که واقعاً قرار است استفاده کنی.

> **نسخه‌ی 0.1.0، پیش‌انتشار اولیه.** سرتاسری روی ویندوز (تنها پلتفرمی که تا حالا روی آن اجرا شده) کار می‌کند. نسخه‌های مک، لینوکس و اندروید از خط تولید CI
> می‌آیند و هنوز روی دستگاه واقعی امتحان نشده‌اند. هر چه دیدی گزارش کن.

## دو حالت، یک سوییچ

سوییچ بزرگ **ساده / پیشرفته** بالای صفحه تعیین می‌کند چه چیزی تست شود. نمودار مسیر زیر عنوان هم همان لحظه شکلش را عوض می‌کند.

| | **ساده** | **پیشرفته** |
|---|---|---|
| به چه سؤالی جواب می‌دهد | *کدام کانفیگ‌های خودم کار می‌کنند؟* | *کدام کانفیگ‌های رایگان از مسیر کانفیگ من کار می‌کنند؟* |
| مسیر | تو ← **کانفیگ** ← AI Studio / Gemini | تو ← **کانفیگ پایه** ← **کانفیگ رایگان** ← AI Studio / Gemini |
| چه چیزی می‌دهی | کانفیگ‌های خودت (لینک، لینک ساب یا base64) یا یک لیست رایگان آماده | یک کانفیگ پایه‌ی سالم، به‌علاوه‌ی لیست رایگان یا کانفیگ‌های paste‌شده |
| پروفایل ضد فیلتر روی چه چیزی اعمال می‌شود | هر کانفیگ تست‌شونده (چون هر کدام از سیستم تو وصل می‌شود) | هاپ اولِ کانفیگ پایه (کانفیگ‌های رایگان داخل تونل آن اجرا می‌شوند) |
| کاربرد معمول | بررسی یک دسته کانفیگ که از قبل داری؛ تست یک کانفیگ پیش از اینکه رویش حساب کنی | کانفیگ کلودفلرت کار می‌کند ولی به **خروجی دیگری** نیاز داری که گوگل قبول کند |
| خروجی | لینک، base64، کانفیگ کامل Xray برای یک کانفیگ | لینک، base64، کانفیگ Chain (`base ← free`) |

## چرا مرورگر لاگین‌شده؟

گوگل ریجن را **برای حساب لاگین‌شده و بعد از بالا آمدن صفحه** بررسی می‌کند. یک درخواست ساده‌ی HTTP (حتی به API جمینی با کلید الکی) از هر کشوری «آزاد» جواب می‌دهد،
برای همین تست‌های اتصال هر کانفیگ زنده را «سالم» می‌زنند. در اندازه‌گیری‌های همین پروژه خروجی‌های US و HK و SG هم بلاک بودند و یک خروجی در طول زمان می‌تواند عوض شود.
تنها سیگنال قابل‌اعتماد، چیزی است که گوگل به کاربر لاگین‌شده نشان می‌دهد؛ همین را می‌خوانیم:

| سرویس | بلاک چه شکلی است |
|---|---|
| AI Studio | ریدایرکت به `/docs/available-regions` |
| Gemini | «Gemini isn't currently supported in your country» |

## دانلود و نصب

نسخه‌ی مناسب سیستمت را از صفحه‌ی [Releases](../../releases) بگیر. هر انتشار فایل `SHA256SUMS.txt` دارد.

| پلتفرم | اپ دسکتاپ (پنجره‌ی نیتیو) | نسخه‌ی وب (UI در مرورگر) | بررسی ریجن |
|---|---|---|---|
| ویندوز | amd64، arm64 | amd64، arm64 | ✅ نیاز به Chrome / Edge / Brave |
| مک | یونیورسال (اینتل + اپل سیلیکون) | amd64، arm64 | ✅ نیاز به Chrome / Edge / Brave |
| لینوکس | amd64 (نیاز به GTK 3 و WebKitGTK 4.1) | amd64، arm64، armv7 | ✅ نیاز به Chrome / Chromium / Edge / Brave |
| اندروید ۸ به بالا | **APK** (arm64-v8a) | برای Termux از سورس بساز (`GOOS=android`) | ❌ فقط حالت «اتصال» |

<details><summary><b>ویندوز</b></summary>

۱. فایل `gemini-config-checker-desktop_<version>_windows_amd64.zip` (یا `arm64`) را دانلود و هر جا خواستی unzip کن.
۲. `GeminiConfigChecker.exe` را اجرا کن. WebView2 داخل ویندوز ۱۰ و ۱۱ هست. اگر SmartScreen هشدار داد: *More info ← Run anyway* (برنامه امضا نشده).
</details>

<details><summary><b>مک</b></summary>

۱. `..._macos_universal.zip` را دانلود و unzip کن و `.app` را به *Applications* ببر.
۲. بار اول: راست‌کلیک روی برنامه ← *Open*. اگر باز هم رد کرد: `xattr -dr com.apple.quarantine "/Applications/GeminiConfigChecker.app"`.
</details>

<details><summary><b>لینوکس</b></summary>

۱. یک بار کتابخانه‌های لازم را نصب کن: `sudo apt install libgtk-3-0 libwebkit2gtk-4.1-0` (دبیان/اوبونتو؛ برای توزیع‌های دیگر معادلش را نصب کن).
۲. `tar -xzf gemini-config-checker-desktop_<version>_linux_amd64.tar.gz` و بعد `./GeminiConfigChecker`.
۳. محیط دسکتاپ نداری؟ نسخه‌ی **وب** را بگیر: `./gemini-config-checker` و `http://localhost:8787` را باز کن.
</details>

<details><summary><b>اندروید</b></summary>

۱. فایل `gemini-config-checker_<version>_android_arm64.apk` را روی خود گوشی دانلود کن.
۲. گزینه‌ی *نصب از منبع ناشناس* را برای مرورگر یا فایل‌منیجرت فعال کن و APK را باز کن.
۳. برنامه را اجرا کن. یک نوتیفیکیشن دائمی («Scanner engine is running») طبیعی است: موتور به‌صورت سرویس foreground اجرا می‌شود تا اسکن‌های طولانی با خاموش شدن صفحه قطع نشوند. با دکمه‌ی **Stop** همان نوتیفیکیشن موتور را خاموش کن.
۴. APK در حالت **«فقط اتصال»** کار می‌کند (بخش [مرجع تنظیمات](#۷-مرجع-تنظیمات)). اندروید اجازه‌ی کنترل یک Chromium لاگین‌شده را به اپ‌ها نمی‌دهد، پس ریجن آنجا قابل تأیید نیست.
۵. APK انتشار با کلید ریپو امضا می‌شود (اگر تنظیم شده باشد)، وگرنه با یک کلید موقت؛ نصب می‌شود ولی بیلد بعدی روی آن آپدیت نمی‌شود و باید اول حذفش کنی.
</details>

<details><summary><b>نسخه‌ی وب (هر سیستم‌عامل، سرور، Termux)</b></summary>

`./gemini-config-checker` همین UI را روی `http://localhost:8787` بالا می‌آورد و مرورگرت را باز می‌کند. فلگ‌ها: `-addr 127.0.0.1:8787`، `-no-open`، `-version`.
UI **رمز ندارد**: روی localhost نگهش دار، یا به‌جای باز گذاشتنش تونل بزن (`ssh -L 8787:localhost:8787 your-server`).
</details>

## راهنمای استفاده

### ۱. اولین اجرا
پنجره سه تب دارد: **اسکن** (چه چیزی و چطور تست شود)، **نتایج** (لیست زنده، فیلتر و دکمه‌های کپی) و **خروجی**.
بالای صفحه سوییچ **ساده / پیشرفته**، وضعیت اسکن و دکمه‌ی تم تیره/روشن است. هر چه وارد می‌کنی با تیک «ذخیره» روی همین دستگاه می‌ماند (روی کامپیوتر مشترک تیکش را بردار).

### ۲. حالت را انتخاب کن
* **ساده**: وقتی کانفیگ‌هایی داری و می‌خواهی بدانی کدام کار می‌کنند، یا می‌خواهی کانفیگی را پیش از اتکا به آن بسنجی.
* **پیشرفته**: وقتی کانفیگ کلودفلرت وصل می‌شود ولی گوگل خروجی‌اش را بلاک می‌کند: کانفیگ‌های رایگان پشت آن زنجیره می‌شوند و خروجی‌های دیگری به تو می‌دهند.
* هر لحظه می‌توانی سوییچ را بزنی. نتایج حالتِ همان اسکنی را نگه می‌دارند که ساخته‌شان؛ تب خروجی و دکمه‌های کپی هم از آن پیروی می‌کنند.

### ۳. ورود با Google (بررسی ریجن)
بررسی ریجن AI Studio و Gemini را به‌جای *خودت* باز می‌کند. یک بار **ورود با Google** را بزن:
۱. یک پنجره‌ی Chrome / Edge / Brave در یک **پروفایل جدا** باز می‌شود که فقط مال همین برنامه است. مثل همیشه وارد شو. برنامه رمز را نمی‌بیند.
۲. وقتی ورود تشخیص داده شود پنجره خودش بسته می‌شود و کارت به «حساب Google متصل است» تغییر می‌کند. ورود برای دفعات بعد هم می‌ماند.
۳. **حساب ثانویه** بهتر است: درخواست‌ها از IPهای مختلف می‌آیند و گوگل ممکن است هشدار «ورود مشکوک» بدهد.
۴. **حذف حساب از برنامه** فقط همان پروفایل خصوصی را پاک می‌کند و به مرورگر و حساب‌های اصلی‌ات دست نمی‌زند.

مرورگر نصب نیست یا روی اندروید هستی؟ در تنظیمات *نوع بررسی* را روی **فقط اتصال** بگذار: بدون ورود و بدون مرورگر کار می‌کند.

### ۴. حالت ساده، قدم‌به‌قدم
۱. کانفیگ‌هایت را در کادر paste کن، هر کدام در یک خط: `vless://`، `vmess://`، `trojan://`، `ss://`. لینک ساب (`https://…`) یا متن base64 هم قبول است.
   کادر را خالی بگذار تا یک لیست رایگان آماده تست شود (پایین‌تر انتخابش کن).
۲. اگر در شبکه‌ای هستی که کانفیگ کلودفلر ساده وصل نمی‌شود، **ضد فیلتر** را روشن نگه دار ([بخش ۶](#۶-پروفایل-ضد-فیلتر)).
۳. وارد شو (بررسی ریجن) یا «فقط اتصال» را انتخاب کن.
۴. **شروع اسکن** (یا `Ctrl`+`Enter`) را بزن و تب **نتایج** را تماشا کن.

### ۵. حالت پیشرفته، قدم‌به‌قدم
۱. **کانفیگ پایه**: کانفیگی که برای خودت کار می‌کند و روی AI Studio دیوار ریجن نمی‌بیند. لینک، یا JSON کامل xray (حتی زنجیره‌ای چندهاپه؛ مثلاً خروجی‌ای که خودش از یک ورکر کلودفلر رد می‌شود) را paste کن.
   همه‌ی کانفیگ‌های رایگان پشت همین مسیر زنجیره می‌شوند.
۲. **ضد فیلتر**: روی هاپ اولِ کانفیگ پایه اعمال می‌شود، یعنی اتصالی که از سیستم تو خارج می‌شود.
۳. **منبع**: یک لیست آماده (`verified` پیشنهاد می‌شود) یا کانفیگ‌های رایگان را خودت paste کن. `custom` هر لینک ساب را می‌پذیرد.
۴. تنظیمات، ورود، **شروع اسکن**. پیش از تست کانفیگ‌های رایگان، ابتدا خود کانفیگ پایه تست می‌شود و اگر به گوگل نرسد، اسکن با پیام روشن متوقف می‌شود.

### ۶. پروفایل ضد فیلتر
داخل ایران کانفیگ‌های کلودفلر ساده معمولاً فقط با تنظیمات زیر وصل می‌شوند
([دستور patterniha / PattN](https://t.me/MatinSenPaii/5469)). مقادیر ممکن است عوض شوند، پس همه قابل ویرایش‌اند؛ دکمه‌ی **مقادیر پیشنهادی** پیش‌فرض‌ها را برمی‌گرداند.

| تنظیم | پیش‌فرض | چه می‌کند |
|---|---|---|
| Finalmask (JSON) | دو ماسک fragment: `tlshello` با `lengths [0,104,1]` و سپس `1-1` با `lengths [114,1]` | ClientHello را تکه می‌کند تا فیلتر نتواند نام سرور را بخواند |
| Fingerprint | `unsafe` | TLS بومی Go به‌جای تقلید مرورگر؛ تا لیست cipher زیر اعمال شود |
| ALPN | `http/1.1` | |
| Cipher suites | لیست ۱۳ تایی دستور | |
| IP تمیز | خالی | آدرس اتصال را عوض می‌کند (دامنه‌ی قبلی به‌عنوان SNI و Host می‌ماند) |

* **خواندن از کانفیگ**: اگر کانفیگ paste‌شده خودش این مقادیر را دارد (`finalmask`، `cipherSuites`، `alpn` در JSON یا پارامترهای لینک `fm`، `ciphers`، `alpn`، `fp`)، این دکمه آن‌ها را وارد فرم می‌کند.
* xray استاندارد برای هر ماسک fragment فقط یک `length`/`delay` می‌شناسد، ولی دستور از `lengths`/`delays` (لیست برای هر تکه) استفاده می‌کند که ویژگی فورک PattN است.
  برنامه همان الگوریتم فرگمنت را در یک فورواردر محلی کوچک پیش از اتصال اجرا می‌کند. فقط ماسک‌های `fragment` پشتیبانی می‌شوند و بقیه با پیام روشن رد می‌شوند.
* بیرون از شبکه‌ی فیلترشده خاموشش کن؛ آنجا فقط تأخیر اضافه می‌کند.

### ۷. مرجع تنظیمات
| تنظیم | پیش‌فرض | معنا |
|---|---|---|
| نوع بررسی | ریجن با مرورگر لاگین‌شده | **ریجن**: AI Studio و Gemini را باز می‌کند و حکم گوگل را می‌خواند (دقیق، ۲۰ تا ۴۰ ثانیه برای هر کانفیگ). **فقط اتصال**: فقط ثابت می‌کند مسیر به گوگل می‌رسد و تأخیر را می‌سنجد (سریع، بدون ورود، ولی ریجن بررسی **نمی‌شود**) |

| بررسی همزمان با مرورگر | ۴ | هر کدام حدود ۲۰۰ مگابایت RAM می‌خواهد؛ روی سیستم کوچک کمش کن |
| تست اتصال همزمان | ۲۰ | مرحله‌ی اول و ارزان که کانفیگ‌های مرده را پیش از مرحله‌ی مرورگر حذف می‌کند |
| تایم‌اوت اتصال | ۱۰ ثانیه | روی اینترنت کند بیشترش کن |
| ذخیره | روشن | کانفیگ‌ها و تنظیمات را فقط در حافظه‌ی محلی همین دستگاه نگه می‌دارد |

### ۸. خواندن نتایج
* **سالم / متصل**: برچسب سفید. در حالت ریجن یعنی شرط «سالم» تو برقرار بوده؛ در حالت اتصال فقط یعنی «رسیده».
* **ریجن بلاک**: گوگل برای حداقل یکی از سرویس‌هایی که شرط کردی دیوار ریجن نشان داده. ستون‌های **AI Studio** و **Gemini** هر سرویس را جدا نشان می‌دهند (`✓ آزاد`، `✗ بلاک`).
* **خطا**: کانفیگ مرده، تایم‌اوت یا مشکل مرورگر؛ روی برچسب بمان تا دلیلش را ببینی.
* **پینگ** تأخیر یک درخواست از کل مسیر است. اولین کاشی تعداد تست‌شده‌ها را نشان می‌دهد و کاشی آخر «پینگ کانفیگ پایه» (پیشرفته) یا «کمترین پینگ» (ساده).
* بر اساس وضعیت فیلتر کن، با نام یا آدرس جستجو کن، با پینگ یا نام مرتب کن و چند ردیف را برای کپی گروهی انتخاب کن.
* **هر حکم یک نمونه است، نه ضمانت.** خروجی یک ورکر کلودفلر بین اتصال‌ها می‌تواند عوض شود؛ پس همان مسیر ممکن است الان قبول شود و یک دقیقه بعد رد. کانفیگی را که می‌خواهی نگه داری دوباره تست کن.

### ۹. استفاده از چیزی که پیدا کردی
* **کپی** لینک اشتراکی را کپی می‌کند. در کلاینتت (v2rayN، Hiddify، PattN، …) یا در فیلد **Chain Proxy** پنل BPB بگذارش.
* **کپی با Chain** (پیشرفته) / **کپی کانفیگ کامل** (ساده) یک کانفیگ آماده‌ی import برای Xray را کپی می‌کند. تب خروجی همین را می‌دهد و می‌تواند فایل `.json` ذخیره کند. کلاینت مقصد را انتخاب کن:

| مقصد | گزینه | finalmask در فایل |
|---|---|---|
| PattN / PattNG | *PattN / PattNG (با finalmask)* | هست |
| Xray / v2rayN با هسته‌ی استاندارد | *Xray / v2rayN استاندارد* | حذف می‌شود (هسته‌ی استاندارد schema فورک را نمی‌شناسد) |

  فایل از تنظیمات کلاسیک `vnext` / `servers` (روی هسته‌ی قدیمی و جدید باز می‌شود)، ورودی mixed روی `10808` و `10809`، DNS با IP ثابت و بلاک UDP/443 استفاده می‌کند.
  در v2rayN: *Servers ← Add custom configuration server* و فایل را انتخاب کن. بدون GUI: `xray run -c file.json`.
* **تب خروجی**: لینک‌ها (هر کدام در یک خط)، ساب base64 یا کانفیگ Xray؛ تعداد را محدود کن، کپی کن یا ذخیره کن.

### ۱۰. نکته‌های اندروید
همان UI، فقط حالت اتصال، و پیش‌فرض ساده. نوتیفیکیشن foreground موتور را در طول اسکن زنده نگه می‌دارد؛ لمس آن برنامه را باز می‌کند و **Stop** موتور را خاموش می‌کند.
«ذخیره در فایل» انتخابگر فایل خود اندروید را باز می‌کند.

## حریم خصوصی و امنیت
* ورود داخل مرورگر خودت انجام می‌شود، نه داخل برنامه؛ کوکی‌ها فقط در حافظه می‌مانند. پروفایل جدا هیچ‌وقت به پروفایل و حساب‌های مرورگر اصلی‌ات دست نمی‌زند.
* ترافیک به گوگل TLS سرتاسری است؛ اپراتور کانفیگ رایگان مقصد را می‌بیند، نه محتوا را. ترافیک حساس را از کانفیگ‌های رایگان رد نکن.
* کانفیگ‌ها و تنظیمات فقط در حافظه‌ی محلی خود برنامه (و فقط با تیک «ذخیره») نگه داشته می‌شوند و فقط از مسیر خودت می‌روند.
* سرور وب روی `127.0.0.1` می‌ماند و `Host`های بیگانه و POSTهای غیر JSON را رد می‌کند، ولی رمز ندارد.

جزئیات و گزارش مشکل: [SECURITY.md](SECURITY.md).

## ساخت از سورس
نیاز به Go (نسخه در `go.mod`). اپ دسکتاپ علاوه بر آن به [Wails v2](https://wails.io) و webview پلتفرم نیاز دارد
(ویندوز WebView2، مک WebKit، لینوکس GTK 3 و WebKitGTK 4.1). اپ اندروید به Android SDK، JDK 17+ و Gradle 8.10 نیاز دارد.

```sh
make test                      # vet + تست‌ها
make web                       # ./dist/gemini-config-checker
make desktop                   # اپ نیتیو با Wails (روی همان سیستم‌عامل مقصد)
make android                   # APK (موتور arm64 + Gradle)
make dist VERSION=0.1.0        # نسخه‌ی وب برای همه‌ی پلتفرم‌ها
```

## انتشار و CI
* `ci.yml`: gofmt، vet و تست روی Linux / Windows / macOS و بررسی کامپایل همه‌ی هدف‌های نسخه‌ی وب.
* `release.yml`: اپ‌های دسکتاپ (ویندوز amd64/arm64، مک یونیورسال، لینوکس amd64)، نسخه‌های وب (لینوکس، ویندوز، مک) و APK اندروید را می‌سازد، `SHA256SUMS.txt` تولید می‌کند و ریلیز `v<VERSION>` را منتشر می‌کند.
  **فقط وقتی یک push روی `main` فایل `VERSION` را عوض کند خودش اجرا می‌شود** (push‌های معمولی فقط `ci.yml` را اجرا می‌کنند): اگر ریلیز آن نسخه هنوز نیست ساخته و منتشر می‌شود و اگر هست، کاری نمی‌کند. برای انتشار نسخه‌ی جدید، `VERSION` و `CHANGELOG.md` را عوض کن و push بزن.
  تگ `vX.Y.Z` منطبق با `VERSION` یا *Actions ← Release ← Run workflow* (با تیک «publish»؛ راه اجرای دوباره‌ی ریلیز ناموفق هم همین است) هم کار می‌کند.
* برای اینکه امضای اندروید بین نسخه‌ها ثابت بماند، این secretها را اختیاری بگذار: `ANDROID_KEYSTORE_BASE64`، `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_ALIAS`، `ANDROID_KEY_PASSWORD`.
